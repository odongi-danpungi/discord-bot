# v5.2.4 참가자 접수 안내 검토

검토일: 2026-10-14 (Asia/Seoul). 직전 개발 기준은 v5.2.3 / 3f76e7bca7358beaaee621f34509e408630c56a7입니다. GitHub main과 실제 Railway는 v5.1.7이며 기존 초안 PR #11에서 개발합니다. Discord·네이버 카페·CHZZK와 기존 Queue·예약·호출·추첨·팀 배정·OBS·방송 운영·제작자 점검·복구 기능을 보존합니다. 이 검토는 참가자 접수 안내와 관련 인증·저장 시점 경계의 검토이며 전체 기존 코드의 신규 전수 감사를 의미하지 않습니다.

## 구현과 표시 기준

참가자 내 참가 화면에 하나의 Discord 접수 현황 카드를 추가했습니다. 현재 접수 인원, 최대 정원, 남은 자리, 추첨 선발 인원과 마감 시간을 구분합니다. 모집 없음·접수 중·정원 도달·자동 정원 마감·시간 마감·운영자 마감·추첨/참석 확인/종료 단계를 표시합니다. 정원이 없으면 무제한이며 잘못된 응답을 무제한으로 해석하지 않습니다.

기존 GET `/viewer/api/participation` 및 서버별 `/w/:guildId/viewer/api/participation` 응답에 `recruitment`를 추가합니다. 새 API 엔드포인트는 없습니다.

| 항목 | 의미 |
|---|---|
| status / reason | open·full·closed·inactive 및 capacity·deadline·manual·progress·no_session |
| maxApplicants / unlimited | 현재 회차 정원. 무제한은 0/true, 모집 없음은 null/false |
| activeApplicants | 현재 Discord 신청자 중 미루지 않은 고유 참가자 수 |
| remainingSlots | 유한 정원에서 max(0, 정원-활성 신청자). 무제한·모집 없음은 null |
| closeAt | 현재 접수 마감 시각. 미설정·모집 없음은 0 |
| drawCount | 접수 정원과 별개인 추첨 선발 인원 |
| duplicatePolicy | 현재 회차의 중복 처리. 모집 없음은 null |

현재 session.intakePolicy snapshot을 사용하며 운영자가 다음 모집용으로 저장한 설정을 읽어 대체하지 않습니다. Discord·네이버·수동 Queue 합계가 아니며 다른 참가자의 이름·ID·Queue 항목을 새 집계에 넣지 않습니다. 미래 예약·미루기는 제외하고 도래한 이월 예약은 포함합니다. 이미 약속한 이월이 정원보다 많아도 삭제하지 않고 남은 자리를 0으로 표시합니다.

이미 닫힌 모집은 자리가 비어도 계속 마감입니다. 운영자가 다시 열면 현재 회차 정책을 유지하며 정원이 가득 찬 열린 모집은 full 상태입니다. 정원이 찬 상태에서는 신규 참가·현재 회차 복귀를 허용하지 않지만 열린 모집의 본인 취소·미루기를 유지합니다. 참가 여부는 최종 저장 시 서버에서 다시 검증하므로 화면에 남은 자리가 있어도 다른 요청이 먼저 정원을 채울 수 있습니다.

## 화면·권한·읽기 경계

마감 시간은 서버 시간 기준으로 표시하고 로컬 시간이 지나면 부적절한 참가·취소·미루기를 차단합니다. 이전 모집 링크는 새 모집의 집계·게임·회차와 작업을 보여주지 않습니다. 응답 누락·잘못된 자료형·조회 실패 시 이전 집계와 참가 버튼을 남기지 않습니다. 준비 확인 조회가 실패해도 새 접수 안내는 표시하며 준비 확인 작업만 비활성화합니다.

요청 세대로 늦은 GET이 더 최신 응답이나 변경 결과를 덮지 않게 합니다. 표시된 회차 ID를 참가 요청에 포함하고 오래된 버튼도 실행 직전에 표시 가능 작업인지 검사합니다. 기존 10초 갱신과 1초 시간 표시를 사용하며 별도 폴링을 추가하지 않습니다. UI는 텍스트로 렌더링하고 외부 문자열을 HTML로 넣지 않습니다.

서버별 접수 GET은 현재 Discord 멤버십을 다시 확인합니다. 기존 동시 확인 요청 공유는 유지합니다. 집계 계산은 로컬 상태만 읽고 저장·카페 게시·CHZZK 호출·역할 부여·토큰 갱신을 실행하지 않습니다. 멤버십 확인에 필요한 Discord 읽기 요청과 구분합니다. 참가자 본인 프로필·호출 토큰 비노출, CSRF·Origin·서버 분리·긴급 잠금 등 기존 보호를 유지합니다.

## 수정한 오류와 남은 동작 한계

- 정원이 가득 찬 모집에서도 참가 가능 플래그를 반환하던 문제를 수정했습니다. 실제 서버의 정원 거절은 유지하며 UI에서도 잘못된 참가 버튼을 숨깁니다.
- 자동 시간 마감이 수동 마감으로 기록되던 문제를 수정했습니다. closeAt을 실제로 지난 경우에만 deadline으로 저장하며 임의 reason 문자열로 결정하지 않습니다. 과거 manual 기록의 원인을 추정해 변경하지 않습니다.
- 저장 순서를 기다리며 마감 시간이 지난 참가·참석 확인이 요청 도착 시각으로 승인될 수 있던 문제를 수정했습니다. 저장 callback에서 경과 시간을 반영하고 실제 OperationsStore 대기열·디스크 바이트 불변 회귀를 추가했습니다.
- 준비 확인 오류가 새 접수 표시를 막는 문제와 조회 실패·권한 만료 뒤 이전 작업이 남는 문제를 수정했습니다. 늦은 응답과 변경 중 조회의 덮어쓰기를 차단합니다.
- 참가 상태 조회가 캐시된 멤버십으로 잠시 허용될 수 있던 경로에 fresh 확인을 적용했습니다. 타 서버와 제작자 API 권한은 유지합니다.
- 현재 모집이 마감된 뒤의 호출 패스는 기존 예약 변경이 실패하거나 Queue 재동기화로 미루기가 취소될 수 있었습니다. 이 상태의 패스 예약 변경을 호출 응답 전에 409로 차단하고 UI에서 진행자에게 요청하도록 안내합니다. 호출 자체의 응답 시간이 남으면 참가 응답은 유지합니다. 정원이 가득 차도 접수 중인 모집의 패스는 유지하며 현재 모집과 무관한 수동 호출도 기존 경로를 사용합니다. 마감 후 패스 예약을 새로 보장하는 기능은 이번에 구현하지 않았습니다.

새 필수 환경변수·권한·Gateway Intent·저장 파일·스키마 변경은 없습니다. 데이터 스키마 2와 기본 비활성 포털을 유지합니다. 롤백은 이전 안내·시간 검증 동작으로 돌아가며 전체 데이터 볼륨과 기존 암호화 키를 보존해야 합니다. 저장소·Release의 기존 서명 정책을 낮추지 않습니다. 별도 부하 벤치마크는 수행하지 않아 처리량 개선 수치를 주장하지 않습니다.

## 배포 준비와 실제 서비스 상태

Railway `/healthz` 읽기 결과는 v5.1.7 / status ok / ready true입니다. main 병합·새 버전 배포·환경변수·볼륨·트래픽을 변경하지 않습니다. 실제 Discord OAuth·네이버 카페 접수·CHZZK 팔로워 역할·서버 A/B 격리·Queue 종료 후 재시작 E2E는 PENDING입니다. 별도 참가자 테스트 계정이 없다는 기존 답변을 유지합니다.

현재 운영 v5.1.7용과 직전 개발 v5.2.3용 Update JSON을 각각 제공합니다. Update JSON은 기존 허용 목록의 코드·테스트와 일부 루트 파일을 업데이트하며 전체 문서·배포 설정은 전체 ZIP에 포함됩니다. 패키지는 무서명 v2이므로 서명 필수 환경의 기존 서명 절차를 사용합니다.
