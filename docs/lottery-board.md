# 뽑기판 (1~100번)

- 스트리머: 포털 → 방송 → 룰렛 → 뽑기판. 사용 여부, 번호 1개당 금액(100~1,000,000치즈), 후원 1건 최대 번호 수(1~20), 등수 개수(1~10등)와 등수별 상품 이름·개수(합계 100개 이하, 나머지는 꽝). 등수 이름은 순서대로 1등·2등…이고 1등 금, 2등 은, 3등 동, 4등부터 초록으로 표시합니다. 바꾼 상품은 다음에 만드는 뽑기판부터 적용됩니다.
- 시청자: 치즈 후원 메시지에 번호를 적습니다(예: `11 23`). 금액 ÷ 번호 1개당 금액만큼, 앞에서부터 엽니다.
- 열 수 없는 경우(이미 열린 번호, 1~100이 아닌 번호, 번호를 덜 적음, 뽑기판 없음, 운영 잠금 중)는 **보류 기회**로 남습니다. 시청자가 채팅으로 다시 말한 번호를 스트리머가 포털에서 대신 엽니다.
- 배치: 새 뽑기판을 만들 때 서버가 암호학적 난수로 섞습니다. 스트리머 API·OBS 화면에는 열린 칸의 결과만 나갑니다. 전체 배치는 제작자 화면(`/creator` → 뽑기판 배치)에서만 볼 수 있고(`GET /api/lottery-board/layout`, 워크스페이스 허용 목록·운영자 권한에 없음), 이 열람은 어떤 기록에도 남기지 않습니다.
- 저장: `operations.json.lottery-board.json`(설정·현재 뽑기판·보류 기회 100개·최근 기록 100개). 후원 메시지와 후원자 채널 ID는 저장하지 않고, 후원자 닉네임은 열린 칸 표시를 위해 저장합니다.
- OBS: `/w/:서버/broadcast/lottery-board?token=...`(방송 토큰). 투명 배경, 새로 열린 칸은 뒤집히며 결과 띠가 나옵니다.
- 테스트 후원: 스트리머 화면 → OBS 테스트. 닉네임과 번호를 넣으면 상품 비율로 무작위 결과를 정해 OBS에 `[테스트]`로 잠깐 보여 줍니다. 실제 뽑기판·보류 기회·기록은 바뀌지 않고, 결과는 서버 메모리에 최근 20개만 둡니다(3초에 한 번, `POST /api/lottery-board/test`). 뽑기판이 있어야 보낼 수 있습니다.
- 연습 모드: `npm run demo` 후 `http://127.0.0.1:3001/portal/` → 연습 방송 서버 → 방송 → 룰렛 → 뽑기판. OBS 화면은 `http://127.0.0.1:3001/broadcast/lottery-board`.
