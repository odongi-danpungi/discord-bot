# v5.2.5 마감 후 호출 패스·예약 복구 검토

검토일: 2026-10-15 (Asia/Seoul). 직전 개발 기준은 v5.2.4 / 28b9205e36a77e09c58c0da68918e4f225ca37f2입니다. GitHub main과 실제 Railway의 기준은 v5.1.7이며 기존 초안 PR #11에서 개발합니다. Discord·네이버 카페·CHZZK, Queue·예약·호출·추첨·팀 배정·OBS·방송 운영과 제작자 점검·복구 기능을 보존합니다. 이번 검토는 호출 패스와 그 예약·저장·화면·권한 경계의 변경을 대상으로 하며 전체 기존 코드의 신규 전수 감사를 의미하지 않습니다.

## 지원 범위와 사용자 동작

현재 Discord 모집의 호출을 받은 참가자는 내 참가 화면이나 Discord 메시지의 **이번판 패스**로 다음판 예약을 저장합니다. 정확한 entry·호출 토큰·본인·모집 ID·게임·회차·신청 상태를 검증하며, 호출의 실제 응답 기한이 남아 있어야 합니다. 요청 도착 시점만으로 승인하지 않고 Queue와 Operations의 저장 순서를 기다린 뒤 기한과 운영 잠금을 다시 확인합니다. 기한과 같은 시각은 만료입니다.

| 현재 모집 단계 | 현재 회차 호출 패스 | 유지하는 제한 |
|---|---|---|
| open | 허용 | 정확한 본인 호출·유효한 호출 응답 기한 필요 |
| 접수 시간이 지난 open | 허용 | 새 참가 접수는 계속 차단 |
| closed: 수동·정원·시간 마감 | 허용 | 일반 모집의 취소·미루기 버튼은 계속 마감 |
| drawn / checking | 409 거절 | 당첨자·참석·팀 결과를 변경하지 않음 |
| ended | 409 거절 | 종료 회차 예약 변경 안 함 |

접수 마감 시간과 호출 응답 기한은 별개입니다. 일반 모집 버튼의 다음판·다다음판 미루기를 마감 후에 개방하지 않습니다. 패스 때문에 추첨 가능한 신청자가 모집 인원보다 적어지면 기존 추첨 검증에서 차단하고 운영자가 모집 인원을 조정해야 합니다. 당첨자·참석·팀을 자동 초기화하거나 추가 선발하지 않습니다. 호출의 참가 응답은 기존 경로를 유지합니다.

수동 Queue와 현재 모집에 연결되지 않은 호출은 기존 Queue 전용 패스를 유지합니다. 그 경로에서 임의의 게임·회차 예약을 만들지 않습니다. Discord와 네이버 계정의 검증되지 않은 닉네임 매핑도 추가하지 않습니다.

## 저장 결정과 Queue 반영

Operations와 Queue를 여러 파일에 걸친 단일 원자적 트랜잭션으로 바꾸지는 않습니다. 기존 JsonStore의 파일별 저장과 복구를 유지하고 다음 절차를 사용합니다.

1. Queue 저장 잠금 안에서 정확한 호출·사용자·기한을 검증합니다.
2. Operations 잠금을 얻은 뒤 현재 회차·단계·기한·운영 잠금을 재검증합니다. 다음판 예약, session.postponed와 호출별 결정 기록을 하나의 Operations 저장에 함께 넣습니다.
3. Queue에 해당 결정의 적용 증거와 자동 진행 기록을 저장합니다.
4. Queue 기본 파일 저장이 끝난 뒤 Operations 결정의 반영 확인을 저장합니다.

Operations 저장이 실패하면 예약과 Queue 응답 모두 수락하지 않습니다. Operations는 저장됐지만 Queue 저장이 실패하면 이미 수락된 결정이 남습니다. 재시작·재시도·호출 진행에서 미완료 결정을 Queue에 먼저 반영하며, 예약 회차를 다시 계산하지 않습니다. 반영 확인 저장만 실패하면 Queue의 적용 증거로 중복 반영을 막고 확인을 재시도합니다. 실제 파일 I/O 실패는 정상 입력 거절과 구분해 종료 시 flush에도 보고합니다.

모든 관련 잠금의 순서는 Queue → Operations입니다. 같은 Queue 경로를 쓰는 저장소 객체들은 Operations 연결과 확인 중인 작업을 공유합니다. Queue flush는 Queue 기본 저장뿐 아니라 그 뒤의 결정 확인 작업과 Operations flush를 기다립니다. 정상 요청 거절을 저장 실패로 바꾸는 기존 오류는 다시 도입하지 않습니다.

오래된 Operations 스냅샷이 최신 패스를 waiting으로 되돌리지 않도록 Queue 저장 콜백에서 연결된 Operations의 최신 상태를 읽습니다. 예약 취소 또는 다음 회차 개설이 먼저 완료됐으면 현재 기준 상태를 반영합니다. 과거 결정으로 취소된 예약을 되살리거나 이미 소비한 예약을 새로 만들지 않습니다.

## 자동 다음 호출과 동시 실행

호출별 자동 진행은 한 번 선정한 다음 대상만 재사용합니다. 다음 참가자가 이미 응답한 뒤 이전 패스 요청을 다시 보내도 그다음 참가자를 호출하지 않습니다. 재시작·시간 만료 처리·다음 호출이 미완료 패스를 복구할 때도 같은 진행 기록을 사용합니다.

수동 호출은 유효한 호출을 Queue에 저장하는 같은 변경 안에서 미완료 진행을 인계받습니다. 없는 참가자나 잘못된 상태로 수동 호출이 거절됐다고 기존 진행을 완료 처리하지 않습니다. 원래 모집 ID·게임·회차가 달라지거나 종료되면 이전 패스의 자동 진행을 중단합니다. 대상 선정, Queue 저장 잠금 획득 뒤, 실제 Discord 전송 직전에 현재 모집·잠금·종료 상태를 재확인합니다.

이미 수락한 패스는 다음 자동 호출 전송 실패로 취소되지 않습니다. 공개 응답은 진행자가 호출 상태를 확인하도록 안내합니다. 외부 Discord 메시지 전송과 로컬 파일 저장 전체의 exactly-once 전송을 보장한다고 주장하지 않습니다. 기존 전송 실패·미확정 처리 범위와 실제 서비스 검증이 계속 필요합니다.

추첨과 패스가 동시에 실행되면 Operations 잠금으로 순서가 정해집니다. 패스가 먼저 저장되면 이후 추첨은 미룬 참가자를 제외합니다. 추첨이 먼저 완료되면 패스는 결과를 지우지 않고 거절됩니다.

## 참가자 화면과 개인정보 경계

새 API 엔드포인트는 없습니다. 기존 참가 상태 응답은 본인 Queue의 `passPending`을 표시하고 확인 중인 호출의 새 응답·신청·예약 변경을 막습니다. 화면에는 **패스 반영 확인 중**과 예약은 저장됐으며 상태를 확인 중이라는 안내를 보여줍니다. 전체 내부 기록을 내려보내지 않습니다. 기존 시간 표시·갱신 흐름을 사용하며 새 커넥터 조회나 추가 폴링을 넣지 않습니다.

기존 Viewer HTML에 고정돼 있던 호출 응답 버튼의 동작 핸들러를 연결했습니다. 동적으로 생성하는 참가 버튼과 고정 호출 버튼 모두 최신 action 플래그·처리 중 상태를 따릅니다. 마감 전용 제한을 없애더라도 추첨·참석 확인·종료·호출 시간 만료와 오래된 모집 링크의 버튼 제한은 유지합니다.

참가자 호출 응답에 서비스의 다음 호출 대상(`result.next`)이 그대로 들어가 다른 참가자의 이름·Discord ID를 전달하던 경로를 수정했습니다. 참가자에게는 본인 entry의 허용 필드, 재시도 여부와 공개용 오류 안내만 반환합니다. 다음 대상의 이름·ID, 호출 토큰·메시지 참조·내부 receipt·자동 진행 기록을 참가자 응답에 추가하지 않습니다. Queue 요약에서도 호출 토큰·내부 적용·진행 기록을 제외하고 운영자 응답은 기존 권한별 필터를 유지합니다.

자동 호출 실패가 HTTP 200 응답의 advanceError로 전달되면서 저장소 내부 경로·원시 오류 메시지가 노출될 수 있던 문제도 수정했습니다. 공개용 고정 안내를 사용하고 상세 오류는 기존 기술 진단 경로로 분리합니다. 토큰·Secret을 새 로그·소스·화면에 넣지 않습니다.

기존 단일 서버 호출 서비스와 서버별 서비스 모두 현재 운영 잠금·종료 검사를 사용합니다. 기존 인증·CSRF·Origin·현재 Discord 멤버십·서버 격리 보호를 유지합니다. 참가자 응답 최소화는 제작자의 기존 복구 데이터 접근 권한을 일반 사용자에게 확장하는 기능이 아닙니다.

단일 서버 시작 순서도 수정했습니다. HTTP runtime과 Release 상태 검사기가 준비된 뒤 호출 복구를 시작하며, 준비 전 호출은 차단합니다. 재시작 대기·코드 적용·롤백·종료 중에는 타이머와 미완료 자동 진행을 일시 정지합니다. 해당 잠금이 풀리면 안전한 tick에서 재개합니다. 비상 잠금 해제는 먼저 기존 호출의 남은 시간을 보존하고 잠금 해제를 저장한 다음, 다음 안전한 tick에서 미완료 진행만 이어갑니다. 잠금 해제 저장이 실패하면 다시 일시 정지하고 외부 호출을 보내지 않습니다. Discord 버튼의 중복 패스 응답은 이미 저장된 결과라는 안내를 표시하며 알 수 없는 내부 오류는 고정 안내로 숨깁니다.

## 데이터·백업·롤백의 제한

데이터 스키마는 2이며 새 파일을 만들지 않습니다. Operations에 `callPassReceipts`, Queue에 내부 적용·진행 필드를 호환 추가합니다. 원본 호출 토큰은 Operations receipt에 저장하지 않고 해당 호출에 결합된 digest만 사용합니다. 필드가 없는 구형 데이터는 허용하지만 잘못된 receipt와 Queue 진행 구조는 저장·복구 경계에서 거절합니다. Operations 백업·복원 지점은 digest가 맞아도 잘못된 결정 구조를 거절합니다.

완료된 Operations 결정은 최근 200건, 미완료 결정은 최대 1,000건으로 제한합니다. 미완료 결정을 임의로 오래됐다는 이유로 제거하지 않습니다. Queue의 완료 진행 기록은 Operations의 보관 여부와 함께 정리하며, 보관 범위를 벗어난 과거 토큰은 새 패스로 재수락하지 않습니다. 한도 초과·증거 충돌은 자동 추측 대신 운영을 차단합니다.

기존 복원 지점은 참가자 등록·Operations를 담으며 Queue 파일까지 포함하지 않습니다. 따라서 미완료 결정이 있는 Operations만 과거로 복원하면 현재 Queue와 맞지 않을 수 있습니다. 해당 호출 증거가 없거나 새 호출로 바뀌면 fail-closed로 중단하고 기록을 보존합니다. 서로 일치하는 **`/app/data` 전체** 백업과 원래 암호화 키를 사용해야 합니다. 새 workspace, registry, 토큰, Queue와 호출 설정을 빼고 data/backups만 복사하는 것은 전체 재해 복구가 아닙니다.

이전 버전은 새 결정 재생·자동 진행 기록을 해석하지 않습니다. 롤백 전 요청·타이머를 중지하고 미완료 패스 결정과 자동 진행을 검토해야 합니다. 대기 중이면 v5.2.5에서 정상 저장·복구를 마친 뒤 전체 볼륨을 백업하거나 제작자가 일치하는 전체 데이터 복원을 계획합니다. 내부 기록 삭제를 복구 절차로 사용하지 않습니다. **이 절차를 자동으로 강제하는 새 Release Center 게이트를 추가한 것은 아닙니다.** 코드 롤백은 운영 파일·외부 Discord 메시지를 자동으로 되돌리지 않습니다.

새 필수 환경변수·Discord 권한·Gateway Intent는 없습니다. 포털은 기본 비활성이고 replica 1의 JSON 파일 단일 프로세스 운영을 유지합니다. 별도 부하 벤치마크를 수행하지 않으므로 처리량·지연 개선 수치를 주장하지 않습니다.

최종 독립 검토에서 Discord ‘내 시참’ 패널의 community call_join·call_pass 오류도 호출 메시지 버튼과 같은 비노출 처리가 필요함을 확인했습니다. 두 경로의 일반 오류·503 오류를 실제 이벤트 핸들러로 검사하는 회귀를 추가했고, 수정 뒤 집중·전체·core를 순차 재실행해 위 최종 수치를 확인했습니다.

가상 데이터·loopback API·파일 저장 실패 주입 검증은 실제 OAuth·Discord 권한·외부 서비스 인증을 증명하지 않습니다. 최종 CI·Release·ZIP manifest·파일 목록과 화면 증거는 전달 보고서에 실제 결과를 기록합니다. 실패가 발생하면 코드 assertion, 저장 I/O 주입과 환경 차단을 구분하며 테스트 제한 시간이나 검증 조건을 낮춰 숨기지 않습니다.

## 배포 준비와 실제 서비스 상태

이번 개발은 GitHub 개발 브랜치와 초안 PR을 대상으로 합니다. main 병합·Railway 새 버전 배포·운영 환경변수·볼륨·트래픽 변경은 수행하지 않습니다. 실제 Discord OAuth·네이버 카페 접수·CHZZK 팔로워 역할·서버 A/B 격리·Queue 종료 후 재시작 E2E는 계속 PENDING입니다. 별도 참가자 테스트 계정이 없다는 기존 답변을 유지합니다.

배포 전에는 현재 코드와 `/app/data` 전체 영구 볼륨을 백업하고 NAVER_TOKEN_KEY·CHZZK_TOKEN_KEY를 유지합니다. Node >=22.22.2, npm ci, production env:check·verify:final, `/healthz`, replica 1과 graceful shutdown을 확인합니다. 공개 포털은 Discord OAuth Redirect에 PUBLIC_BASE_URL origin + `/portal/auth/callback`을 등록하고 DISCORD_CLIENT_SECRET을 Secret에 저장한 후 실제 계정 검증을 거쳐 활성화합니다. 비밀값은 Git·채팅·로그에 넣지 않습니다.

현재 운영 v5.1.7용과 직전 개발 v5.2.4용 Update JSON을 제공합니다. 기존 허용 목록의 코드·테스트와 일부 루트 파일을 갱신하며 전체 문서·배포 설정은 전체 ZIP에 포함합니다. 무서명 v2 패키지는 기존 서명 필수 정책을 낮추지 말고 필요한 서명 절차를 적용합니다. 패키지의 코드 롤백 검증은 위 운영 데이터의 미완료 결정 검토를 대신하지 않습니다.
