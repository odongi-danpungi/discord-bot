# 룰렛 기능 검토 — 2026-10-19

## 적용 범위

현재 v5.2.7 기반 개발 브랜치에 추가한 Unreleased 기능이다. 버전·필수 환경변수·Operations 스키마 2와 기존 Discord, 네이버 카페, CHZZK, Queue, 추첨, 레이스, 복구 기능을 유지한다.

- 메뉴: 방송 → 룰렛 → 직접 입력 룰렛(2026-10-20 이동, 이전: 통합 운영 → 방송 도구 → 룰렛). 기존 단일 서버 대시보드와 서버별 사용자 포털에 연결한다.
- 직접 입력한 항목 또는 해당 서버 Queue의 `waiting` 참가자 2~100개를 동일 확률로 선발한다. Queue가 100명을 초과하면 일부만 임의 선발하지 않는다.
- 직접 입력은 NFC·양끝 공백·대소문자를 무시하여 중복을 거절한다. 이름은 1~80 Unicode 코드 포인트이며 제어·방향 제어·손상 문자를 거절한다. Queue는 표시 이름이 같아도 서로 다른 항목 ID를 유지한다.
- 서버의 `crypto.randomInt` 결과와 요청 영수증을 같은 Operations 원자 저장에 기록한 뒤 응답한다. 화면의 회전은 저장된 `winnerIndex`를 재생한다.
- Queue 순서·상태·호출, 예약, 기존 게임 추첨·팀 결과를 변경하지 않으며 외부 메시지·API 쓰기를 실행하지 않는다.
- `/룰렛`은 현재 서버의 운영 화면 링크를 비공개로 안내한다. 서버 관리 권한 또는 기존 관리자 역할을 검사하며 HTTPS 기본 주소가 없으면 값 노출 없이 설정을 안내한다.

## 권한·복구

인증, CSRF, 기존 운영자 `broadcast` 권한을 적용한다. Queue 항목·Queue 출처 기록·Queue 추첨에는 `queue` 권한도 필요하다. 서버별 조회는 현재 Discord 운영 권한을 새로 확인하며 참가자에게 운영 자산이나 결과를 제공하지 않는다.

룰렛 revision을 비교하고 Queue 출처는 Queue revision도 비교한다. 원자 저장 대기 뒤 긴급 잠금·안전 종료·배포/롤백 전환·재시작 대기 상태를 재검사한다. 결과 기록 20개와 중복 방지 영수증 100개를 제한 보관한다. 같은 요청은 Queue의 현재 상태와 revision 검사보다 먼저 기존 결과를 반환한다. 일반 응답 캐시 대신 결과와 같은 저장소의 영속 영수증을 사용한다.

브라우저는 응답 유실·5xx·손상된 JSON·다른 요청 ID의 결과를 확정하지 않는다. 원래 body와 요청 키를 보존하고 새 실행을 잠근다. 사용자가 같은 요청을 다시 확인하거나 GET 기록에서 자기 요청을 찾도록 하며 자동 재추첨·폴링은 하지 않는다. 브라우저 뒤로가기 캐시 복귀도 미확정 요청을 보존한 조회로 처리한다.

보관 정보는 추첨 당시 이름·내부 Queue 항목 ID·결과·요청 식별 정보다. Discord 사용자 ID·네이버 계정 키·호출 토큰·OAuth 토큰·Secret은 추가하지 않는다. 일반 snapshot에는 룰렛 내부 상태를 넣지 않으며 전용 조회는 영수증과 fingerprint를 반환하지 않는다. localStorage/sessionStorage에 참가자 이름을 저장하지 않는다. 기존 전체 데이터 백업과 복원 지점 검증에 룰렛 무결성 검사를 연결한다.

## 검토 중 수정한 문제

1. Express가 대소문자·마지막 슬래시 변형을 허용하여 일반 응답 캐시를 거칠 수 있던 실행 경로를 정규 경로로 제한했다. 단일 서버 `/api`와 서버별 `/w/<guild>/api`를 모두 허용한다.
2. 권한이 회수된 운영자의 조회가 이전 멤버십 캐시를 사용할 수 있던 경로에 fresh authorization을 연결했다.
3. 공통 오류 분류기가 명시적 503을 400으로 바꾸던 문제를 수정했다. 운영 데이터 사용 불가는 비밀 정보 없는 고정 503 안내로 처리한다.
4. 응답의 요청 ID 검증, 서버와 동일한 UI 중복 검사, 뒤로가기 복귀와 이전 응답의 경합 처리를 추가했다.

첫 전체 실행의 3개 실패는 환경 차단이 아닌 서버별 정규 API base 검사 오류였다. 이를 수정한 뒤 해당 서버별 집중 회귀 6개가 통과했고, 최종 코드로 전체 검사를 다시 실행하여 모두 통과했다.

## 검증

- 실행 환경: Windows, Node.js 24.19.0. 요구 버전 ≥22.22.2 및 설치 의존성 검사 PASS.
- JS 문법 검사: 295개 PASS.
- 신규 룰렛 집중 회귀: 코어 46개, API 8개, Discord 명령 8개, UI 16개, 실제 workspace platform 6개.
- 최종 `verify:final`: 1,082/1,082 PASS. 실패·취소·건너뜀·환경 차단 0개.
- UI 동작은 JSDOM으로 검증했다. 이번 기능의 실제 브라우저 시각 QA·실제 Discord 계정 E2E는 PENDING이다.
- 실제 Railway 배포·변수·볼륨·트래픽 변경은 수행하지 않았다. 신규 외부 연결 성공을 주장하지 않는다.

## 배포 후 확인

전체 `/app/data`와 기존 암호화 키를 먼저 보존한다. 새 코드로 배포한 뒤 서버별 관리자 로그인, 직접 입력 및 Queue 추첨, 권한 없는 참가자 접근 거부, 같은 요청 결과 확인, 재시작 후 기록 유지, 긴급 잠금 차단을 확인한다. `/룰렛`의 명령 등록·공개 HTTPS 링크·실제 운영 계정 권한도 확인한다. 실서비스 확인 전에는 개발 브랜치의 기능으로 취급한다.
